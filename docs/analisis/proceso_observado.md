## Situación concreta

Una ciudadana presenta una solicitud de constancia de no adeudo municipal. El encargado recibe la documentación, registra los datos y genera el expediente `EXP-2026-0001`, que debe quedar disponible para consulta por su código.

| DNI | 72845136 |

| Fecha | 02/10/2026 |

## Flujo de atención

1. El ciudadano presenta la solicitud administrativa.
2. El encargado recibe los datos personales y del documento.
3. Se identifica el expediente con un código único.
4. Se verifica que la información esté completa.
5. Se registra el expediente.
6. La información queda almacenada para consulta posterior.
7. Cuando se necesita, se busca el expediente por su código.

## Actores

| Actor | Responsabilidad |
|---|---|
| Ciudadano solicitante | Entrega la solicitud y proporciona sus datos |
| Encargado de Mesa de Partes | Recibe, revisa y registra el expediente |
| Mesa de Partes Digital | Organiza, valida, busca y conserva los registros |

## Problema general

Organizar el registro de expedientes para que la información se ingrese correctamente, se mantenga disponible y se localice rápido.

## Problemas específicos

- Información incompleta si no se validan los campos obligatorios.
- Códigos duplicados si no se verifica la unicidad.
- Búsqueda manual poco práctica con muchos registros.
- Expedientes sin criterio uniforme de organización.
- Pérdida de datos si no se almacenan de forma permanente.

## Necesidad identificada

Un prototipo que registre expedientes de forma estructurada y facilite su consulta posterior, con un flujo sencillo acorde al curso.
